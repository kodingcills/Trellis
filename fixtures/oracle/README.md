# Oracle catalog — labeling methodology and provenance

This directory is the **ground truth** for Benchmark A (oracle validity).
It is authored independently of any Trellis machinery — the invalidation
engine that will later be tested against these labels does not exist yet
(oracle-first, spec §33). Nothing in `catalog.json` is generated by, or
derived from, Trellis code.

## Label provenance (the only permitted sources)

1. **fixture-construction** — the fixture was authored by hand; the
   complete set of definitions, call sites, imports, and subclass
   relations is known by construction because every file was written for
   this fixture.
2. **python-import-semantics** — expected relationships under Python 3.11
   import/attribute resolution rules (aliasing, re-export, inheritance).
3. **textual-reference-cross-check** — cheap independent recomputation:
   on the BASE state, the string `refresh_token` occurs in exactly one
   file (`auth/tokens.py`), so its caller/reference sets are empty by
   exhaustive text inspection; implementor classes are found by the
   `(AuthProvider):` pattern in exactly two files. Enforced mechanically
   by the `trellis-oracle` test crate.
4. **hand-reviewed-call-graph** — each catalog entry's per-projection
   labels were cross-checked against the full fixture source by hand.

A future benchmark may compare Trellis outputs against these labels
**without circularity**: the labels never reference Trellis outputs, and
the fixture source contains no Trellis-specific annotations.

## Conventions

- **Canonical symbol form:** dotted Python path, e.g.
  `auth.tokens.refresh_token`, `api.webhooks.handle_refresh`.
- **References vs callers:** a `References` projection counts
  non-definition occurrences (imports, binding uses, call sites); the
  definition site itself is never a member. A re-export is therefore a
  reference but never a caller.
- **Artifact consequences:** every non-baseline mutation enumerates **all
  seeded artifacts** in `artifact_consequences` — there is no
  "unlisted ⇒ unchanged" default; absence from the table is a schema
  violation (enforced by the `trellis-oracle` crate).
- **Projection keys:** `kind(subject, scope)` with kinds matching the
  frozen spec §20 DSL (`Callers`, `References`, `Implementations`,
  `Signature`, `FileContent`), subjects in canonical form, scope one of
  `File | Module | Package | Repository`.
- **Expected values:** `empty_set`, `set` (members sorted, unique),
  `text` (canonical string), `changed` / `unchanged` (for file-content
  projections where the digest is defined by content, not by this
  catalog).
- **Mutation graph:** every mutation has a `parent` (`BASE` or another
  mutation id). Applying a mutation's `ops` to its parent's tree yields
  the mutated state. Chains are acyclic and validated mechanically.
- **Artifact validity vocabulary:** `VALID | STALE | UNKNOWN` with
  authority `AUTHORITATIVE | PROVISIONAL` (frozen spec §11, §12). A
  structural-set artifact reverts to VALID when a reevaluated value is
  unchanged (set-equality contract); a FACT whose proposition is now
  false is STALE, and one whose coverage evidence is degraded is UNKNOWN
  (spec §8).

## Files

- `catalog.json` — the machine-readable catalog (schema
  `trellis-oracle-catalog/1`).

## The one rule that outranks everything

If a label here ever conflicts with what the Trellis implementation
produces, the label wins until a human reviews the discrepancy. Labels
are never edited to match implementation output; that is a BLOCKER
(`.agent/QUALITY_GATES.yaml → REPAIR_POLICY.never`).
